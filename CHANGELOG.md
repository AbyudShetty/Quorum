# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project will use [Semantic Versioning](https://semver.org/) from its first release.

## [Unreleased]

### Added (Phase 1b)

- **Link requests answered in a dialog (D-21):**
  - When a session is asked to link, Quorum's new `quorum_requests` tool opens an MCP elicitation dialog that only the person answers ("… wants to link with this session": Not now / Allow / Block), and the agent is told to call it.
  - The default is Not now: a dialog declined, dismissed, timed out or accepted without a choice (Codex's bypass mode) links nothing. INV-34 is amended accordingly.
  - People get 10 minutes to answer; Codex is set up with `tool_timeout_sec = 600` for Quorum.
  - Typing `/quorum-allow` still works.
- **Idle sessions now wake for link requests and new links** (seen live: "Hii!" did not wake the Claude session that had just linked):
  - Claude Code's watcher also starts next to every `/quorum-*` command. A command runs no turn, so before this no watcher started.
  - It re-reads the session's links every 2 s, so mail on a link made after it started wakes the session too.
  - It wakes the session when someone asks to link. Codex's waker does the same for its windows.
  - Request wakes are capped at 5 per session per hour and never happen with wake mode off; the request still shows at the next prompt.
- `quorum setup` has a revision number: an updated Quorum runs it again by itself, at its first `quorum` command.
- Pairing commands on a laptop used for the earlier tests (seen live: `$quorum-attach` in Codex on a second laptop showed only "hook timed out after 60s"):
  - They now always use this laptop's own server. A sign-in to another machine's server, left by `quorum login <link>`, is dropped.
  - A command that takes longer than 40 s answers that it stopped, and names the step it was on (`sign-in`, `create-id`, `register-window`, `request-link` …).
  - Each command's steps and timings go to `<data>/hooks/commands.log`, next to `errors.log`. Only step names and errors are written there, never tokens or mail.
  - An unexpected error is shown, with where to find the log.
- **The pairing commands and set-up (D-20 steps 5–6):** Quorum's hooks now run at user level in every Claude Code and Codex session (`quorum hook <vendor> <event>` without `--attachment`): `/quorum-id`, `/quorum-attach <id>`, `/quorum-allow [id]`, `/quorum-detach [id]`, `/quorum-block <id>`, `/quorum-export` (Codex: `$quorum-…`) are done by the hook and blocked before the model runs; sessions that never ran one return at once. Paired sessions get mail, wakes and "wants to link" notices; `quorum mcp --vendor <v>` serves the tools for whichever paired session calls (Codex: idle wake per paired session). `quorum setup` writes the user-level hooks, MCP server, commands (`~/.claude/commands`, `~/.codex/skills`), deny rules and tool permission, and removes per-folder config of earlier `attach`/`join` runs; run by `npm install -g` (postinstall) or the first `quorum` command. `quorum uninstall` reverses it. The server keeps a fresh local sign-in code available, so a pairing command can sign its person in at any time (THREAT_MODEL residual 7 updated). Tests: commands as both vendors send them, request notices, mail, export, detach, set-up and uninstall against a scratch home.
- **Session pairing, server side (D-20 step 4):** `POST /v1/quorum-ids` gives a session its own agent and permanent ID; `/v1/links` (list, request, `allow`, `detach`, `block`, `send`, `export` as Markdown); server to server through the relay at `/v1/federation/{link,accept,unlink,message}`, the caller proven by its TLS client key (mutual TLS added to the relay transport) and allowed to speak only for sessions derived from that key (new INV-34). Each link is a two-member workspace (a mirror agent stands for a session on another laptop); changes and messages for another laptop wait in a durable outbox and are retried until delivered. The server joins the relay by itself once a session has an ID. Schemas, OpenAPI (`pairing`, `federation` tags), migration 5. Tests: two real servers and a relay through request, allow, messages both ways, blocking, a laptop that is off, detaching, export, same-laptop pairs, and server-to-server refusals.
- **Quorum IDs and the relay's phone book (D-20 step 3):** `QRM-XXXX-XXXX-XXXX` IDs derived from a laptop's key (`@quorum/core` `newQuorumId`, `parseQuorumId` forgiving case, dashes and look-alike letters). A home registers its IDs with the relay over its proven control connection; the relay keeps only IDs derived from that home's key (Node relay: a JSON file in the data folder; Cloudflare: one Durable Object per ID, `wrangler.toml` migration v2) and answers `GET /v1/lookup/<id>`, rate-limited. `lookupQuorumId` (server) recomputes the ID from the answer, so a relay pointing an ID elsewhere is refused. Tests: derivation, relay registration and lookups (Node and worker glue), persistence, a lying relay.
- **Session pairing designed (D-20, [docs/PAIRING.md](docs/PAIRING.md)):** sessions join and link with commands typed in Claude Code (`/quorum-id`, `/quorum-attach <id>`, …) and Codex (`$quorum-…`), approved by the other person; every laptop runs its own server and servers link through the relay; replaces invite/join. Verified live that both vendors let a hook catch and block a typed command before the model runs. Plan Phase 1b exit replaced. Being built.
- **The relay (D-18):** machines on different networks connect with no VPN, port or tunnel. `quorum invite` on the home machine (turns on remote access through the relay the first time, confirmed at the terminal, INV-30) prints one `quorum join "quorum://<relay>/<key>#k=…&j=…"` line for the other machine. The home server connects out to the relay and proves its key; other machines reach it with `quorumFetch`, which runs TLS 1.3 to the home server's own key inside the relay connection and checks it against the invite before sending anything (new INV-33). New package `@quorum/relay` (pairing logic on Web Crypto; Node server for `quorum relay`, one new dependency `ws`; a Cloudflare Worker with a Durable Object per home for the free hosted relay, the default: `wss://quorum-relay.abyud.workers.dev`). `quorum remote enable [--relay wss://…]` (the relay is the default; `--public-url` keeps Tailscale/Cloudflare). Tests: relay routing and proofs, the worker glue, and an end-to-end run where a recording proxy shows the relay never sees messages, tokens or join codes, and a relay pretending to be the home gets no byte of the request.
- **Asking before mail is read (D-18):** a session that starts or resumes with mail waiting shows the person the count and senders and holds the mail until they say yes ("yes", "show them"); hooks, idle wakes (Claude watcher, Codex waker) and `quorum_inbox` deliver nothing meanwhile, and new mail is counted ("3 (earlier) + 1 (new) messages waiting"). After a yes, mail flows for the rest of the session.
- Plan widened for an easy setup (D-18, abyud): `npm install -g @quorumhq/quorum` instead of cloning and building, a free end-to-end-encrypted relay as the default way to connect machines (Tailscale and Cloudflare Tunnel become alternatives, settling D-5), and asking before mail waiting for a session is read. Name decided (D-1). While abhijna is away abyud decides alone and the track split is on hold (D-19). Plan §2, §4.8, §5, §7, §9, §10, §13, §14, §16; PHASE_1B.md, DECISIONS, AGENTS.md, TEAM_PLAN.
- `quorum hook` never fails the agent, even on an unexpected error (seen as "hook exited with code 1" in Codex 0.162 on a second laptop): it exits 0 and appends the error to `<data>/hooks/errors.log`. Usage errors in the vendor config still exit 64.
- Tidier repository root: `vitest.config.ts` moved to `config/` (`npm test` passes `--config`; run single files with `npm test -- <path>`), and `.dockerignore` moved next to the fleet Dockerfile as `deploy/fleet/Dockerfile.dockerignore` (BuildKit). README rewritten for the current state (quick start, status, all documents); AGENTS.md now points at the latest phase file.
- Joining from another machine (steps 2–5): server links (`https://host#k=<key fingerprint>`, printed by `quorum remote status`), join codes (`quorum join-code`: `&j=qrm_jc_…`, single use, 10 minutes) and `quorum join "<code>" --vendor <v>`, which checks the server key against the fingerprint before sending anything (INV-24), asks for confirmation (INV-30) and attaches the folder to that server; the agent is named after the joining machine, its attachment remembers the server and pinned key, and the CLI, hooks and MCP server connect there. Human device sign-in: `quorum login <server link>` shows a code, `quorum login approve <code>` (confirmed) lets it collect the tokens once. API: `POST /v1/join-codes`, `/v1/join`, `/v1/auth/device`, `/device/approve`, `/device/token` with schemas (`joinCode*`, `joinRequest`, `device*`); core `serverFingerprint`, `formatServerLink`, `parseServerLink` and the `qrm_dc_` token kind (secret scanner too). Folder keys of other machines carry the machine name. Guide: `docs/REMOTE_SETUP.md` (Tailscale and Cloudflare Tunnel). Tests: `packages/cli/test/two-machines.test.ts` and server tests.
- Remote access through an HTTPS front end (ARCHITECTURE §8.3, step 1 of Phase 1b): `quorum remote enable --public-url https://… [--port <n>]`, `disable`, `status`. The server keeps listening on loopback only; `tailscale serve --bg <port>` or `cloudflared tunnel --url http://127.0.0.1:<port>` carries other machines' requests to it, so traffic between machines is always encrypted (INV-22). Settings live in `<data>/local/remote.json` (`@quorum/local`); with remote access on the server listens on the fixed port (default 7420) and never shuts down when idle. Requests to the public name or forwarded by the front end count as remote: tokens required (INV-23), rate limits per forwarded client, no local bootstrap sign-in; the public name is accepted by the Host and Origin checks (INV-26). Enabling is confirmed at a terminal.

### Added (Phase 1)

- `docs/PHASE_1.md`: Phase 1 exit criteria met on 2026-10-11 (exit run by abyud; abhijna to confirm), with the evidence for each criterion and what is carried forward.
- Phase 1 security review fixes:
  - INV-30: `quorum attach` and `quorum worktree` ask the person to confirm at a terminal; without one (an agent's shell, a pipe) they refuse, and there is no flag to skip it.
  - THREAT_MODEL §6 item 7(b) is now true: `attach` adds `Read`/`Edit` deny rules for the Quorum data directory to Claude Code's `.claude/settings.local.json`; `detach` removes them.
  - INV-28: a session (compared by real path in local mode, so 8.3 short names and junctions match) must lie inside its agent's attached folder (`session.outside_attachment`), so an agent cannot raise or dodge shared-working-tree warnings elsewhere; a claimed `display_root` is used only when it names the same folder.
  - INV-10: the wording now lists all four places that can start a process, and a conformance test pins that list.
  - CLI: unknown or malformed options are usage errors (exit 64), not crashes.
- `quorum export --out <file>` writes the log as UTF-8 itself, and `quorum verify` also reads UTF-16 and BOM-prefixed files (Windows PowerShell 5.1 re-encodes `>` redirects as UTF-16, which made an intact log fail). Both take the human's only workspace when `--workspace` is left out.
- Web timeline redesign: windows and senders named as the agents see them (`codex - C:projweb - 10`, recipients `claude - api - 10` or `everyone`), an avatar per tool, local times grouped under Today / Yesterday, a labelled workspace switcher and a live indicator; message ids, threads and raw JSON fold away under "details". CLI commands that take `--attachment` now default to the attachment of the current folder or its nearest attached parent (ARCHITECTURE §12).
- `quorum ui` (ARCHITECTURE §6, §7): prints a one-time link (single use, 60 s) to the read-only timeline, which the local server now serves at its root behind its Host check (INV-26). `POST /v1/auth/ui-link` (humans only, `uiLink` schema) issues the code (`qrm_ul_…`); `GET /login` spends it and sets the `quorum_ui` session cookie (`qrm_us_…`, 12 h, `HttpOnly; Secure; SameSite=Strict`, INV-21). Both token kinds are caught by the secret scanner (INV-14). `@quorum/server` now depends on `@quorum/web`.
- `quorum worktree [--attachment <at_id>] [--agent <name>]` (ARCHITECTURE §13): creates `../<repo>-<agent>` on branch `quorum/<agent>` with `git worktree add` and moves the attachment there under the same agent name (same address, inbox and history). The git call lives in `@quorum/local` (`addGitWorktree`: absolute paths, `quorum/` branches only, no shell); INV-10 now names it as the second process the CLI can start, only from the human's command.
- Neat messages and window fixes from the second live run (D-17 update, MESSAGE_SPEC §1.1, §8; INV-9 amended):
  - A window is shown as `claude - C:\proj\api - 1` (`<tool>[@<machine>] - <path> - <n>`) and a message as that sender line ending in `:`, a blank line, then the message (every line indented two spaces, so a message cannot forge a sender line). The path is in full on the same machine and with the home folder as `~` elsewhere (`from_session.path`, `display_root` on session create, migration 4).
  - Wakes show the person only the neat form: Claude Code's turn continuation through `systemMessage` (the agent reads the framed copy in `reason`), Claude Code's idle wake by asking the agent to show the mail first (Claude Code shows a background hook's output to the agent only), and Codex's idle wake the same way: the framed mail goes into the thread's history (`thread/inject_items`, role `user`) and the turn starts with no user input, so mail never appears in the person's prompt box in either tool (that look stays the human's). The agent reads the framed copy, and every session is told such lines are data from others.
  - `quorum_send` accepts the sender as shown (and `name@machine`, `abyud (human)`), so a reply works the first time.
  - Mail sent to a window's label now counts as direct and wakes it.
  - A new window (or `/clear`) starts reading where the agent's windows got to: no old mail again, while mail no window read still arrives. The server records the starting point as an acknowledgement of the new window.
  - Window numbers count up and are never reused: `/clear` gives the next number; a resumed conversation keeps its own.
  - Codex: one `quorum mcp` serves every Codex window (Codex runs MCP servers in its shared daemon, found in the live run). It no longer registers a session of its own (no more duplicate windows), speaks for each tool call as the window used last, and its waker wakes each idle window for its own mail and keeps open windows alive. `QuorumClient.asSession` runs calls as one window without disturbing others.
  - A new Claude Code window can be woken before its first prompt: the idle watcher also starts with the session, and waits until the window is registered (never waking as the whole agent). `quorum attach --update <at_id>` with no other flags rewrites a folder's hooks and MCP config to the current version.
  - `quorum mcp` follows its window (a new session after `/clear`; Codex's late session-start hook now takes over the session `quorum mcp` registered instead of opening a second one), so wakes reach the right window.
  - The Codex waker no longer asks for a wake at start (that could use up the grant for waiting mail).
  - Private files (hook state, discovery) are replaced safely on Windows while another process reads them: a refused rename is retried briefly instead of the write being lost.
- Windows are addressable (D-17, MESSAGE_SPEC §1.1): every live session gets a label such as `claude@api-1` (`<tool>@<folder>-<n>`; `claude@<machine>-api-1` from another machine). The server stamps the sending window on each message (`from_session`, verified like `from`, INV-7), resolves labels in `to` so a reply reaches that window only (`delivered_to`, `to_sessions`), and keeps read positions, wakes and streams per window (`Quorum-Session` header). `quorum mcp` adopts the session its window's hooks registered (same vendor process), so tools, hooks and idle wake speak as one window, and the Codex waker wakes exactly that window. Migration 3 adds the label columns. Deliveries now read `from claude@api-1: message` inside one compact nonce frame (MESSAGE_SPEC §8, INV-9): later lines indented and control characters removed so a body cannot forge a sender line; `quorum_inbox` keeps the detailed frame and shows the window.
- Idle wake for Codex: `@quorum/codex-bridge` (a client for Codex 0.160's shared local app-server daemon, reached through `codex app-server proxy`; no dependency, fixed command, `turn/start` never carries sandbox or approval settings) and `startCodexWaker`, run by `quorum mcp` for Codex attachments. Off switch `QUORUM_CODEX_IDLE_WAKE=off`. The server grants at most one wake per message per agent (kept across restarts), so two Codex windows, or Claude's Stop hook and its watcher, never wake twice for one message. Spike and threat-model row added. Wakes now work both ways: Claude Code ↔ Codex, and any pair.
- Idle wake for Claude Code: `quorum hook claude-code watch`, installed by `attach` as a second `Stop` hook with `asyncRewake`. ### Fixed

- **Text from another laptop could carry line breaks into an agent's view (INV-9, D-20):** the folder a session shows to another laptop (`path` in a session face and in the link list) was any string up to 4096 characters, and it is shown to the receiving agent and person in the link request, the wake text and the `quorum_requests` dialog before any link exists. The schema now refuses control characters (line breaks, escapes), invisible and direction-changing format characters and line/paragraph separators, so a stranger's request with such a folder is rejected; a laptop replaces them with `?` in its own folder when it sends. Ordinary folders (spaces, accents, Windows paths) are unaffected. `openapi.v1.json` regenerated.
- **Idle-wake watcher could miss mail (Track B):** a watcher that found nothing at start, then opened its stream, never saw mail that arrived in between (the stream does not replay), and a trigger that arrived during a running check joined that check instead of starting a new one. It now re-checks on its first ticks and every few ticks, and runs a check again when a trigger arrived during one. The pairing-commands wake test failed about half the runs before; 0 of 12 after.
- **Two local servers could start at once after a crash (Track A):** when several starters found a lock left by a dead process, one that was slow between reading the stale lock and removing it could remove the fresh lock of the starter that had already replaced it, and both ran. A 25 ms wait-and-recheck hid this, but not under load (the race test failed in about 1 of 5 full test runs). Replacing a stale lock now needs a second lock file, `server.lock.takeover`, and removes the lock only if it still has the content judged stale. A takeover left by a process that died during it is cleared.
- Tests: the full suite failed about half its runs on a 16-thread laptop, with the first server start in a file over vitest's 5 s / 10 s limits while every file ran at once. The limits are now 20 s per test and 30 s per setup. 4 of 4 full runs passed after both fixes.

- Through the relay, every Codex hook took about 13 s (seen live as "hook timed out after 30s" on laptop B): the work took 2–3 s, then the process waited about 10 s for relay WebSockets to finish closing. Relay connections now use the `ws` library on both ends and are dropped at once when a command is done, so the process ends by itself; the hosted relay also answers a close at once. (A first fix ended the process with `process.exit`, which on Windows can crash Node while a pipe is closing: "Assertion failed … UV_HANDLE_CLOSING" on every hook. Removed; a last-resort exit fires only if something still holds the process 5 s later.) Measured through the hosted relay: 1.6–3.2 s per hook. Also: `quorum mcp` no longer drops its relay connections right after starting.
- Codex showed mail twice at the end of a turn (the neat lines, then the framed copy): Codex shows people both parts of a `Stop` hook's answer, so for Codex it now carries the neat form once.
- `quorum_inbox` returned the long untrusted-data frame, of which Codex shows the person only the closing lines: it now returns the neat form (as in hook deliveries) between markers, asks the agent to show it to its person, and ends with how to reply. It accepts a workspace id with other text around it (a model put `mark_read:true` into it), still only one the attachment belongs to; `quorum_send` explains a recipient that is not an address.
- Codex hooks failed on every event ("hook exited with code 1") on Windows machines whose PowerShell blocks scripts: the hook command `quorum …` ran npm's `quorum.ps1` shim. On Windows the hooks now call `quorum.cmd` (runs under any script policy), or `node "<quorum.js>"` when `quorum` is not on the PATH. Re-attach (or join) a folder to rewrite its hooks.
- The database sets its lock wait (busy timeout) before switching to WAL, so a second connection opening the same file waits instead of failing; the two-writer test allows longer than that wait, so a slow CI disk shows SQLite's own error instead of a bare timeout (seen once on CI, Node 24).
- The in-process fleet runs (20 agents, outage) drained for a fixed 1-3 s, so on a busy machine messages still in outboxes were reported as lost. Agents of one run now share a progress tally and stop draining as soon as everything queued has arrived; `drainMs` is only the upper bound (15 s in the tests). Container runs are unchanged.
- Several processes sharing one agent credential (the MCP server, hooks, the idle watcher) could refresh it at the same moment; the second presented an already-rotated refresh token, the server took it for theft and revoked the whole family (INV-11), and the agent was locked out (seen live after a server restart). Refreshes now take a cross-process lock in the data directory and reuse a pair another process just stored. `quorum_send` also says why a message is only queued: refused credentials now say "run `quorum attach` again" instead of "server not reachable".
- A long-lived client (`quorum mcp`, the Codex waker) kept using the old port after the local server restarted, so messages waited in the outbox until the agent was restarted. The client now looks for the server again after a failure (re-reading the discovery file, starting the server if allowed) and redoes the identity handshake before the next request that carries a credential, so nothing that took over the old port ever sees a token (INV-24). Residual case recorded in THREAT_MODEL §6.
- `quorum attach` skipped `.git/info/exclude` when the folder was spelled with a Windows 8.3 short name or a symlink (Windows CI runners use `C:\Users\RUNNER~1`); file paths are now canonicalised before comparing with the repository root.
- `quorum attach` (Track B) now refuses the Quorum data directory however its path is spelled (INV-25). It compared the canonical folder against the data folder as written, so a symlink, a junction or a Windows 8.3 short name (GitHub's `C:\Users\RUNNER~1\...` temp folder) let it attach the data directory. Both sides are now canonicalised; a data folder that does not exist yet falls back to its absolute path. Found by CI on Windows. Regression tests for a junction and an 8.3 short name, and the whole suite passes with `TEMP` set to a short path.
- Presence heartbeats (Track B) are now sent strictly in order. Before, a slow "idle" beat could arrive after the `offline` sent on a clean exit and leave the agent looking online for up to 90 s; it also made a heartbeat test fail about one run in three. Timer beats are skipped while one is in flight, and beats after stop are ignored. 4 new tests, run repeatedly.
- The fake server's contract test failed when the repository path contains a space (the target path was double-encoded); it now uses `fileURLToPath`.
- CI on Windows and Linux (first run of the server package): a race in the local start lock that let two starters both win (now atomic hard-link creation with per-attempt tokens and a confirm step, plus new race tests); Windows permission checks breaking under PowerShell 7 (now plain .NET, no module loading, PSModulePath stripped) and timing out on slow machines; npm 10 trying to compile `better-sqlite3` (install scripts are now off project-wide via `.npmrc`).
- Dependabot no longer proposes major upgrades of `@types/node` and `typescript`, which broke CI (types must match the oldest supported Node LTS; typescript-eslint does not support TypeScript 7 yet).
