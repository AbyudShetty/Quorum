## [Unreleased]

### Added (Phase 1)

- Neat messages and window fixes from the second live run (D-17 update, MESSAGE_SPEC §1.1, §8; INV-9 amended):
  - A window is shown as `claude - C:\proj\api - 1` (`<tool>[@<machine>] - <path> - <n>`) and a message as that sender line ending in `:`, a blank line, then the message (every line indented two spaces, so a message cannot forge a sender line). The path is in full on the same machine and with the home folder as `~` elsewhere (`from_session.path`, `display_root` on session create, migration 4).
  - Wakes show the person only the neat form: Claude Code's turn continuation through `systemMessage` (the agent reads the framed copy in `reason`), Claude Code's idle wake by asking the agent to show the mail first (Claude Code shows a background hook's output to the agent only), and Codex's idle wake the same way: the framed mail goes into the thread's history (`thread/inject_items`, role `user`) and the turn starts with no user input, so mail never appears in the person's prompt box in either tool (that look stays the human's). The agent reads the framed copy, and every session is told such lines are data from others.
  - `quorum_send` accepts the sender as shown (and `name@machine`, `abyud (human)`), so a reply works the first time.
  - Mail sent to a window's label now counts as direct and wakes it.
  - A new window (or `/clear`) starts reading where the agent's windows got to: no old mail again, while mail no window read still arrives. The server records the starting point as an acknowledgement of the new window.
  - Window numbers count up and are never reused: `/clear` gives the next number; a resumed conversation keeps its own.
  - Codex: one `quorum mcp` serves every Codex window (Codex runs MCP servers in its shared daemon, found in the live run). It no longer registers a session of its own (no more duplicate windows), speaks for each tool call as the window used last, and its waker wakes each idle window for its own mail and keeps open windows alive. `QuorumClient.asSession` runs calls as one window without disturbing others.
  - A new Claude Code window can be woken before its first prompt: the idle watcher also starts with the session, and waits until the window is registered (never waking as the whole agent). `quorum attach --update <at_id>` with no other flags rewrites a folder's hooks and MCP config to the current version.
  - `quorum mcp` follows its window (a new session after `/clear`; Codex's late session-start hook now takes over the session `quorum mcp` registered instead of opening a second one), so wakes reach the right window.
  - The Codex waker no longer asks for a wake at start (that could use up the grant for waiting mail).
  - Private files (hook state, discovery) are replaced safely on Windows while another process reads them: a refused rename is retried briefly instead of the write being lost.
- Windows are addressable (D-17, MESSAGE_SPEC §1.1): every live session gets a label such as `claude@api-1` (`<tool>@<folder>-<n>`; `claude@<machine>-api-1` from another machine). The server stamps the sending window on each message (`from_session`, verified like `from`, INV-7), resolves labels in `to` so a reply reaches that window only (`delivered_to`, `to_sessions`), and keeps read positions, wakes and streams per window (`Quorum-Session` header). `quorum mcp` adopts the session its window's hooks registered (same vendor process), so tools, hooks and idle wake speak as one window, and the Codex waker wakes exactly that window. Migration 3 adds the label columns. Deliveries now read `from claude@api-1: message` inside one compact nonce frame (MESSAGE_SPEC §8, INV-9): later lines indented and control characters removed so a body cannot forge a sender line; `quorum_inbox` keeps the detailed frame and shows the window.
- Idle wake for Codex: `@quorum/codex-bridge` (a client for Codex 0.160's shared local app-server daemon, reached through `codex app-server proxy`; no dependency, fixed command, `turn/start` never carries sandbox or approval settings) and `startCodexWaker`, run by `quorum mcp` for Codex attachments. On mail the server allows (INV-29) it starts one turn in an idle Codex session, headed as coming from Quorum, not the human, with the framed mail; busy sessions keep getting mail through hooks. Off switch `QUORUM_CODEX_IDLE_WAKE=off`. The server grants at most one wake per message per agent (kept across restarts), so two Codex windows, or Claude's Stop hook and its watcher, never wake twice for one message. Spike and threat-model row added. Wakes now work both ways: Claude Code ↔ Codex, and any pair.
- Idle wake for Claude Code: `quorum hook claude-code watch`, installed by `attach` as a second `Stop` hook with `asyncRewake`. It holds the live stream open and, when the server grants a wake for new mail (INV-29), prints the framed mail and exits 2 to wake the idle session; it stands down when wake mode is off, when replaced (newer watcher, new prompt, session end) or after 8 hours. `QuorumClient.stream` (SSE with resume) added for it. Tested against the real server.
- First live run on Windows (Claude Code ↔ Codex through the real local server): MCP tools, hook delivery, replies and server-granted mid-turn continuation all worked; results in ADAPTER_CONTRACT §9. Fixes from the run: exec-form launches use Node plus the CLI path (npm shims need a shell on Windows); `attach` writes Claude Code's `.mcp.json` (pre-approved) instead of printing a command PowerShell mangles; `quorum_send` accepts plain `text` for notes; `quorum mcp` ends its session and says offline when the vendor closes it.
- `@quorum/adapter-hooks` and `quorum hook <claude-code|codex> <event>`: Claude Code and Codex hooks for session start (session with the real vendor id, presence, introduction, unread mail), prompts and tool calls (new mail as `additionalContext`, framed, acknowledged after framing, long mail in parts), stop (continues the turn only when the server grants a wake, never twice in a row) and session end (offline and session closed at once). Never fails the agent; warns the human if the identity check fails. Tested against the real server.
- Server-decided wakes (INV-29): `POST /v1/workspaces/{ws}/wake` (agents) with the `wakeRequest`/`wakeDecision` schemas. The server applies the wake mode, `wake_types`, hourly budget and agent-only-loop pause; grants are `wake.granted` events, replayed at start so a restart never refills the budget. Core `WakeGovernor.recordWake`. Contract case for both servers; the fake server answers too.
- `quorum attach` writes the vendor configuration (Claude Code MCP server in `.mcp.json`, pre-approved, and hooks in `.claude/settings.local.json`; Codex hooks and MCP table in `.codex/`), merging with existing settings and keeping every file out of git via `.git/info/exclude`; `detach` removes exactly those entries; `--no-config` prints instead. The INV-10 conformance scan now covers `adapter-hooks` too.
- `@quorum/server` (Track A), the `/v1` API: every operation in `openapi.v1.json` on Fastify and SQLite. Registry changes and their events commit in one transaction (INV-8); tokens are stored as hashes, rotate, and reuse of a rotated refresh token revokes the family (INV-11); owner sign-in with the bootstrap code; attach with canonical roots, the data directory refused however it is spelled (INV-25), and stable agent identity across detach and re-attach (D-12); sessions with `shared_worktree` notices from `system:quorum` to every agent in the working tree (INV-28); presence from heartbeats (online/offline transitions recorded); revocation and detach close streams at once (INV-13); unknown recipients rejected; rate limits per agent and for requests without a token (INV-15, INV-23). Passes the shared contract suite. New dependency: `fastify` (MIT), planned in ARCHITECTURE §11.
- Local mode end to end: `startLocalServer` (private data directory, start lock, loopback only, discovery file, bootstrap code, idle shutdown) and auto-start: CLI commands start the server in the background when none is running. The spawn lives in `@quorum/server` with a fixed command line, so the CLI and adapter sources still cannot start processes (INV-10).
- CLI: `quorum serve --local`, `quorum stop` (signals only a process that passed the identity check, then removes its leftover files) and `quorum workspace create|list`; `login` starts the server first. IC2 test: the CLI and the adapter client against the real server (login, workspace, attach two vendors, send, framed inbox, shared-worktree notices, export and verify, stop).
- Contract suite: cases for the bootstrap sign-in, attachment PATCH and DELETE, the inbox default, folder and presence, sessions and shared-worktree notices, using optional target hooks (`makeFolder`, `bootstrap`, `advanceClock`). The fake server now sends `shared_worktree` notices too. Core gained `systemNotice` and the `rate_limited` error kind.
- Contract answers to the adapter contract's six open questions (Track A half, all additive; the fake server and Track B code keep working unchanged):
  - `POST /v1/auth/local-bootstrap` and the `localBootstrapRequest`/`localBootstrapResponse`/`localBootstrapFile` schemas: in local mode the server writes a single-use, 10-minute `qrm_bc_` code into `<data>/local/bootstrap.json` on each start; the CLI exchanges it for the owner human's tokens. Core gained the `bootstrap` token kind (also caught by the secret scanner, INV-14) and `decideBootstrap`; the server gained `LocalBootstrap` (only the hash in memory, file removed once spent or expired, two simultaneous exchanges cannot both succeed).
  - `PATCH /v1/attachments/{attachment}` (humans only) with `attachmentUpdate`, and a standalone `attachment` schema.
  - `GET …/inbox`: an omitted `after` now starts after the caller's last acknowledged `seq`.
  - Agent list entries may carry `folder` (folder name only, never a path).
  - Heartbeat interval: every 30 s, offline after 90 s, immediate `offline` on a clean session end (MESSAGE_SPEC §5.10).
- `@quorum/local` (Track A): the local-mode files (data directory and Windows ACL lock-down, discovery file, bootstrap code file, start lock) moved out of `@quorum/server` so adapters and the CLI can use them without SQLite. `@quorum/server` re-exports them, so existing imports keep working. - `@quorum/fleet` and `deploy/fleet` (Track B): the simulated fleet. N fake agents (same client library as the real adapters) exchange direct messages through a `/v1` server; a summary reports lost, misdelivered and duplicated messages, errors and latency percentiles. ### Fixed

- The in-process fleet runs (20 agents, outage) drained for a fixed 1-3 s, so on a busy machine messages still in outboxes were reported as lost. Agents of one run now share a progress tally and stop draining as soon as everything queued has arrived; `drainMs` is only the upper bound (15 s in the tests). Container runs are unchanged.
- Several processes sharing one agent credential (the MCP server, hooks, the idle watcher) could refresh it at the same moment; the second presented an already-rotated refresh token, the server took it for theft and revoked the whole family (INV-11), and the agent was locked out (seen live after a server restart). Refreshes now take a cross-process lock in the data directory and reuse a pair another process just stored. `quorum_send` also says why a message is only queued: refused credentials now say "run `quorum attach` again" instead of "server not reachable".
- A long-lived client (`quorum mcp`, the Codex waker) kept using the old port after the local server restarted, so messages waited in the outbox until the agent was restarted. The client now looks for the server again after a failure (re-reading the discovery file, starting the server if allowed) and redoes the identity handshake before the next request that carries a credential, so nothing that took over the old port ever sees a token (INV-24). Residual case recorded in THREAT_MODEL §6.
- `quorum attach` skipped `.git/info/exclude` when the folder was spelled with a Windows 8.3 short name or a symlink (Windows CI runners use `C:\Users\RUNNER~1`); file paths are now canonicalised before comparing with the repository root.
- `quorum attach` (Track B) now refuses the Quorum data directory however its path is spelled (INV-25). It compared the canonical folder against the data folder as written, so a symlink, a junction or a Windows 8.3 short name (GitHub's `C:\Users\RUNNER~1\...` temp folder) let it attach the data directory. Both sides are now canonicalised; a data folder that does not exist yet falls back to its absolute path. Found by CI on Windows. Regression tests for a junction and an 8.3 short name, and the whole suite passes with `TEMP` set to a short path.
- Presence heartbeats (Track B) are now sent strictly in order. Before, a slow "idle" beat could arrive after the `offline` sent on a clean exit and leave the agent looking online for up to 90 s; it also made a heartbeat test fail about one run in three. Timer beats are skipped while one is in flight, and beats after stop are ignored. 4 new tests, run repeatedly.
- The fake server's contract test failed when the repository path contains a space (the target path was double-encoded); it now uses `fileURLToPath`.
- CI on Windows and Linux (first run of the server package): a race in the local start lock that let two starters both win (now atomic hard-link creation with per-attempt tokens and a confirm step, plus new race tests); Windows permission checks breaking under PowerShell 7 (now plain .NET, no module loading, PSModulePath stripped) and timing out on slow machines; npm 10 trying to compile `better-sqlite3` (install scripts are now off project-wide via `.npmrc`).
- Dependabot no longer proposes major upgrades of `@types/node` and `typescript`, which broke CI (types must match the oldest supported Node LTS; typescript-eslint does not support TypeScript 7 yet).

### Changed

- README status table and repository layout now list the Track B packages, fake server, conformance and e2e tests and the fleet.
- Outage testing (Track B): client requests now time out (default 15 s) and report the server as unreachable instead of hanging; the fake server can simulate a dropped or frozen server (`setOutage`); fleet agents send through the real outbox and retry with a flusher; `deploy/fleet/run.mjs --outage N` drops the server mid-run. Verified in Docker: 50 agents, 5 s outage, 1500 of 1500 messages delivered; a server that never returns fails the run with `unsent`/`lost`. 5 new tests.
- `@quorum/adapter-mcp` and the fake server (Track B): session registration and shared-working-tree warnings (INV-28). The adapter finds the git working tree and common directory by reading `.git` (no `git` process, checked against real git), registers a session at start, and warns the agent in its instructions and `quorum_status` when another agent is in the same folder; the fake now assigns stable repo/worktree ids and reports shared trees. 11 new tests.
- `@quorum/adapter-mcp` (Track B): presence heartbeats every 30 s with an immediate `offline` on a clean end (`quorum mcp` starts them); the sender header now shows the sender's folder name from the agent list. `docs/ADAPTER_CONTRACT.md` records Track A's answers to the six open questions and what each changed in the adapters and CLI. 7 new tests.
- `@quorum/cli` and `@quorum/adapter-mcp` (Track B): `quorum login` (bootstrap code swap, only after the identity check), `quorum attach` / `attach --update` / `detach` (uses `POST`, `PATCH`, `DELETE /v1/attachments`; credentials to the keychain, record to the data directory, vendor setup printed), and the inbox now relies on the server's default (after the last ack), so the adapter's own read-position file is removed. 10 new tests.
- `tests/fakes/fake-server` (Track B) follows the post-freeze `/v1` additions: local bootstrap login, `PATCH /v1/attachments/{id}`, the inbox default (after the last ack), `folder` in the agent list and heartbeat presence (online for 90 s, offline at once on `status: offline`). 12 new tests; the 16 contract tests still pass.
- `@quorum/adapter-mcp` and `@quorum/cli` (Track B) now use `@quorum/local` for the data directory and discovery file; the adapter's duplicate copy and its "equals the server's" test are gone, and `@quorum/adapter-mcp` no longer depends on `@quorum/server` (so adapters do not pull in SQLite).
- Tidier repository root (no content changed): `CONTRIBUTING.md` and `SECURITY.md` → `.github/` (GitHub still finds both), `QUORUM_PLAN.md` → `docs/` (byte-identical, still excluded from formatting), `CLAUDE.md` → `.claude/CLAUDE.md` (imports `../AGENTS.md`), Prettier settings → `package.json`, `tsconfig.base.json`/`tsconfig.build.json` → `config/`. All links and paths updated.
- Phase 0 closed by joint decision (D-16): spec reviews and interviews waived; real interviews moved to Phase 5; five simulated interviews added (labelled as not counting).
- Rejection flow decided: a rejection opens a discussion (agent justifies, humans share thoughts, a human ends it); new `approval_required_from` lets users require approval for every gated action or only from a chosen risk up, never skipping `critical` (INV-32).
- Repository process recorded (D-15): `main` unprotected for now; no AI agent runs git — agents give the humans the commands to run (AGENTS.md).
- Plan and specs now cover three topologies: same machine/different folders (T1), same machine/mixed vendors incl. a shared folder (T2), and different machines (T3). Adds zero-network **local mode** (loopback, auto-start, tokens, server identity pinning), attachments/sessions and flexible agent identity, shared-working-tree detection and a worktree helper, `local_ref` artifacts, per-vendor delivery and wake modes for Claude Code and Codex (verified against official docs), local-mode latency targets, and invariants INV-23–INV-31.
- Phases re-sequenced (D-8, accepted provisionally): Phase 1 is Claude Code ↔ Codex on one machine; cross-machine moves to Phase 1b; Codex moves from Phase 4 to Phase 1.
- Decisions are made jointly by both maintainers; D-8–D-13 recorded; D-5 marked for revisit (Cloudflare Tunnel proposed).
- Spec open questions answered (D-14): message body limit 96 KiB; approvals needed set per action; independent approver always required for high/critical; sensitive files shareable only via the gated `artifact.share_sensitive`; high-risk approvals from the terminal with Windows Hello (browser passkey as fallback). The rejection flow stays open.
